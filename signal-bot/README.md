# Signal-бот черги

Бот слухає **чат-джерело**, шукає в повідомленнях ключові слова і пересилає
знайдені повідомлення в **чат черги**. Кожне переслане повідомлення адресується
(@-згадкою і голосовим повідомленням) наступному користувачу з черги.

```
Чат-джерело                         Чат черги
"Був приліт на Лісовій"   ──►   📨 Нове повідомлення
                                 Від: Тарас
                                 Ключові слова: приліт

                                 Був приліт на Лісовій

                                 🔔 Прийшла черга @Петро 8/14
                                 Реакція ➕ — беру, ➖ — не можу (на відповідь 5 хв)
                                 🔊 «Прийшла черга Петро, 8 з 14»
```

`8/14` — номер людини у списку черги (в порядку додавання) / скільки всього людей у черзі.

Аналіз повідомлення: знайдені ключові слова, телефони, посилання, кількість вкладень.

## Як працює черга

1. Нове повідомлення отримує перший у черзі, після чого він переміщується в кінець.
2. Відповідальний ставить **реакцію** на повідомлення бота:
   - ➕ (або 👍 ✅) — беру. Повідомлення закрите.
   - ➖ (або 👎 ❌) — не можу. Бот одразу кличе наступного з черги.

   Замість реакції можна відповісти на повідомлення бота (свайп → відповідь) текстом `+` або `-`.
   Враховується тільки відповідь того, чия зараз черга.
3. Якщо ніхто не відреагував за **час на відповідь** (`/timeout`), бот кличе наступного.
4. Той, хто поставив ➖ або не відповів, переміщується залежно від режиму (`/mode`):
   - `end` — у кінець черги;
   - `next` — у початок, тобто він отримає наступне нове повідомлення.
5. Одне повідомлення не пропонується одній людині двічі. Якщо всі в черзі відмовились
   або не відповіли — бот пише «Ніхто з черги не взяв це повідомлення».

Голосове повідомлення генерується через Google TTS (пакет gTTS, потрібен інтернет).
Перевірити, як звучить: `voice-test.bat` (Windows) або `python3 bot.py voice-test`.

Черга, налаштування й повідомлення, що чекають відповіді, зберігаються в `state.json`,
тому переживають перезапуск.

## Технічно

Бот — один Python-файл (`bot.py`) поверх
[signal-cli-rest-api](https://github.com/bbernhard/signal-cli-rest-api).

Якщо акаунт бота — ваш особистий, ваші дії з телефона (команди, реакції, повідомлення
в чаті-джерелі) теж обробляються.

## Встановлення на Windows

### 1. Docker Desktop
1. Потрібна Windows 10 (22H2) або Windows 11, 64-біт.
2. Завантажте і встановіть [Docker Desktop](https://www.docker.com/products/docker-desktop/).
   Під час встановлення залиште галочку **Use WSL 2**. Якщо Windows попросить
   оновити WSL — погодьтесь (або в PowerShell від адміністратора: `wsl --update`).
3. Перезавантажте комп'ютер, запустіть Docker Desktop і дочекайтесь статусу
   *Engine running*.
4. У Docker Desktop → Settings → General увімкніть
   **Start Docker Desktop when you sign in**, щоб бот піднімався після перезавантаження.

> Якщо Docker пише про віртуалізацію — увімкніть її в BIOS (Intel VT-x / AMD-V / SVM).

### 2. Файли бота
Завантажте репозиторій (Code → Download ZIP на GitHub) і розпакуйте, наприклад,
у `C:\signal-bot`. Далі працюємо в теці `signal-bot`.

### 3. Прив'язка акаунта Signal
1. Двічі клацніть `groups.bat` — він створить `config.json` і запустить Signal API
   (перший раз завантаження займе кілька хвилин; помилку про `bot_number` поки ігноруйте).
2. Відкрийте в браузері
   `http://localhost:8080/v1/qrcodelink?device_name=queue-bot`.
3. На телефоні: Signal → Налаштування → Пов'язані пристрої → **+** → проскануйте QR.

Акаунт має бути учасником **обох** груп: тієї, яку слухаємо, і чату черги.

### 4. Налаштування
1. Відкрийте `config.json` у Блокноті, впишіть `bot_number` (номер акаунта, `+380…`)
   і збережіть.
2. Знову запустіть `groups.bat` — він покаже список груп з їх `id`.
3. Скопіюйте `id` (вигляду `group.xxxx…`) у `source_group` і `queue_group`,
   впишіть `keywords` і, за бажанням, `admins`. Збережіть (кодування UTF-8 —
   Блокнот у Windows 10/11 зберігає так за замовчуванням).

### 5. Запуск
- `start.bat` — запустити бота (працює у фоні, перезапускається сам).
  Після оновлення файлів бота теж запускайте `start.bat` — він перезбере бота.
- `stop.bat` — зупинити.
- Логи: `docker compose logs -f bot` (у терміналі в цій теці).
- Після зміни `config.json` — `docker compose restart bot`.

Щоб бот не пропускав повідомлення, вимкніть сон комп'ютера:
Параметри → Система → Живлення → Сон → **Ніколи**.

## Встановлення на Linux / macOS

```bash
cp config.example.json config.json          # вкажіть bot_number
docker compose up -d signal-api
# прив'язка: http://localhost:8080/v1/qrcodelink?device_name=queue-bot
docker compose run --rm bot python bot.py groups   # id груп -> config.json
docker compose up -d
```

## Налаштування (`config.json`)

| Поле | Опис |
|---|---|
| `api_url` | адреса signal-cli-rest-api |
| `bot_number` | номер бота, `+380…` |
| `source_group` | id групи, яку слухає бот |
| `queue_group` | id групи, куди пересилаються повідомлення і де керують чергою |
| `keywords` | список ключових слів |
| `case_sensitive` | враховувати регістр (за замовч. `false`) |
| `whole_word` | шукати лише цілі слова. За замовч. `false` — шукається підрядок, тобто «тривог» знайде і «тривога», і «тривоги» |
| `admins` | номери, яким дозволено `/add`, `/remove`, `/skip`, `/clear`. Порожній список — дозволено всім |
| `response_timeout_minutes` | хвилин на відповідь ➕/➖, після чого кличеться наступний (`0` — вимкнено) |
| `pass_mode` | `end` — хто не взяв, іде в кінець черги; `next` — отримає наступне повідомлення |
| `accept_reactions` / `decline_reactions` | які емодзі означають «беру» / «не можу» |
| `voice` | надсилати голосове повідомлення (`true`/`false`) |
| `voice_template` | текст голосового; `{name}`, `{pos}`, `{total}` |
| `state_file` | файл для збереження черги |

Основні поля можна задати й змінними середовища: `SIGNAL_API_URL`, `BOT_NUMBER`,
`SOURCE_GROUP`, `QUEUE_GROUP`, `KEYWORDS` (через кому), `ADMINS` (через кому), `STATE_FILE`.

## Команди (пишуться в чаті черги)

| Команда | Дія |
|---|---|
| `/add @Олена @Петро` | додати користувачів у чергу (згадкою або номером `+380…`) |
| `/remove @Петро` | прибрати з черги |
| `/join` / `/leave` | додати / прибрати себе |
| `/queue` | показати чергу в порядку отримання |
| `/next` | хто отримає наступне повідомлення |
| `/skip` | пропустити поточного |
| `/clear` | очистити чергу |
| `/timeout 5` | час на відповідь: `5` (хв), `30s`, `1h`; `0` — не передавати автоматично |
| `/mode end` / `/mode next` | хто не взяв — у кінець черги / отримає наступне повідомлення |
| `/voice on` / `/voice off` | увімкнути / вимкнути голосові |
| `/settings` | поточні налаштування |
| `/tasks` | повідомлення, що чекають відповіді |
| `/help` | довідка |

`/add`, `/remove`, `/skip`, `/clear`, `/timeout`, `/mode`, `/voice` — лише для адміністраторів
(якщо список `admins` у конфігу не порожній). Налаштування, змінені командами, зберігаються
і мають пріоритет над `config.json`.
